# 기존 실험 최종 재검증 (v0.5)

## 목적
학생이 제안한 쟁점 중 K의 혼합 전략 삽입 필요성과 역전 구간의 차이를 기존 v0.4에서 관찰한 실제 데이터에 근거하여 재검증한다. 알고리즘 코드는 변경하지 않는다. v0.4의 병목 최적화 결과는 이미 확보했으므로 반복하지 않는다.

## 실행 (Windows PowerShell)
프로젝트 최상위 폴더에서 실행한다. v0.4의 세 실행 파일이 필요하다.

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
py benchmark/followup.py --quick
py benchmark/followup.py
```

`--quick`은 동작 점검용이며 보고서에 사용하는 정규 측정이 아니다. 기존 설치 환경 외에 Python 라이브러리를 설치할 필요가 없다. 정규 측정은 입력 7쌍, 3라운드, 7묶음(목표 2ms)이며 입력별 중앙값과 IQR을 계산한다. 기본 시드 97000에서 각 실험별 오프셋을 더한다. `--seed`, `--inputs`, `--rounds`, `--reps`, `--output`을 명시적으로 변경할 수 있다. 기본 출력은 `results/local-followup`이며 이미 존재하면 새 이름으로 저장한다.

## 표 읽기
1. K의 단일 분할: v0.4와 같은 one_level 시간 측정. 128블록 주변의 성능 저하가 재현되는지 확인. 계측 파일은 one_level을 지원하지 않으므로 124/128/132에서 임계값 n-1을 사용하는 동등한 단일 분할로 호출 수와 말단 크기를 확인한다.
2. K 삽입: 동일 TT에서 K 없음/기존 K/개선 K를 비교. K 호출이 없는 경우에는 작은 시간 차이를 삽입의 인과적 효과로 해석하지 않는다. 기초비용 절감과 추가 비기초비용은 각 입력에서 차이를 계산한 뒤 중앙값을 구한다. 양수의 순절감(기초 절감-추가 비용)이 예상되는 이득이다. 계측은 일반 실행과 별도로 하므로 완전히 일치할 필요는 없다.
3. 개선 정책: v0.4 정책 CSV에서 고른 Immediate KT/TT=128/512,128/256 및 Deferred=256/512를 새로운 시드에서 기존 H 정책과 비교한다. 선택된 후보 범위에 대한 평가이며 전역 최적값이 아니다. 1보다 큰 가속률은 변경 정책이 빠르다는 의미이다.

`raw.csv`에는 묶음별 시간, `ratios.csv`에는 입력별 쌍비율의 중앙값과 사분위수, `counts.csv` 및 `leaves.csv`에는 재귀 호출 수와 말단 분포, `phases.csv` 및 `policy_differences.csv`에는 구간별 시간 및 입력별 비용 차이, `environment.txt`에는 실행 환경과 실행파일 해시가 저장된다. `console.txt`는 터미널 결과이다. 보고서에는 정규 실행 캡처를 사용한다. IQR은 신뢰구간이 아니며 측정 시간의 작은 차이는 단정하지 않는다.

## 연구 과정과 AI 활용 기록
학생은 재귀 알고리즘별 병목, 혼합 전략에서 K 생략 여부, S 개선에 따른 역전점 이동을 후속 연구 질문으로 제시했다. AI는 v0.4 학생 PC의 CSV를 점검하여 K가 실제로 호출되지 않는 크기, 고정 TT의 다른 후보에서 K가 유리한 경우, 128블록에서의 비단조성을 발견하고 후속 측정 스크립트를 작성했다. 학생은 v0.4의 병목 최적화 결과를 토대로 K에서는 재조합 개선이, T에서는 보간 전체에 대한 비용 재설계가 최선의 발전방향임을 제시했다.
